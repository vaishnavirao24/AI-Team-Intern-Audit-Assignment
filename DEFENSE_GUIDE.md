# 30-minute defense guide

## Your 90-second opening

"I audited two leadership claims. First, the tokenizer report used a ten-line corpus and a language-dependent denominator. I rebuilt the analysis on 1,012 aligned FLORES sentences in five languages and compared GPT-2 with multilingual mT5. The fair offline cost measure is tokens per aligned sentence because sentence IDs hold content approximately constant. Second, the serving report confused total processed tokens with generated-token goodput. The apparent long-prompt speed-up disappears when output tokens are divided by wall time, and throughput collapses after KV-cache saturation causes preemption. Every number I will show is regenerated by two commands."

## Numbers you must derive without notes

- KV bytes/token: `2 * 28 * 8 * 128 * 2 = 114,688 B = 112 KiB`.
- KV memory budget: `24 * 0.92 - 8.4 - 1.6 = 12.08 GB`.
- Max full sequences: `floor(12.08e9 / 114,688 / 4,096) = 25`.
- Batch-24 goodput: `24 * 512 / 61.16 = 200.92 output tok/s`.
- Independent check: `1,607.4 * 512 / 4,096 = 200.93 output tok/s`.
- Batch-48 goodput: `48 * 512 / 151.41 = 162.30 output tok/s`.
- Cap-24 predicted improvement: `200.92 / 162.30 - 1 = 23.8%`.

## Likely counterfactuals

**If KV cache were fp8:** bytes/token would halve to 57,344, so theoretical sequence capacity would roughly double from 25 to 51, subject to runtime support, accuracy and other overhead. Do not promise batch-48 throughput without a load test.

**If generation length changed:** recompute output goodput using `requests * generated_tokens / wall_time`; longer generation also keeps KV blocks alive longer and can move the preemption threshold.

**If prompts were not parallel:** tokens/sentence would no longer hold content constant, so cross-language ratios could reflect topic/length differences rather than tokenization.

**Why not tokens/byte:** bytes describe storage encoding, not equal meaning; UTF-8 gives Indic code points more bytes than ASCII, which can make an inefficient tokenizer look favourable.

**Can we swap only the tokenizer:** normally no. Token IDs and embeddings are learned together with the model; a tokenizer change generally requires compatible training/adaptation. Route model-tokenizer pairs.

**Why prompt engineering in Part C:** three-week deadline, no external generation budget, limited reviewer coverage and zero added serving model. The kill criterion prevents continuing if style gain or meaning preservation is insufficient.

## Do not overclaim

- FLORES is not production chat.
- mT5 tokenizer efficiency does not prove mT5 model quality.
- The batch-24 cap is specific to this model, hardware and 4,096-token workload.
- Four Part C languages have no native reviewer under the stated constraint; label them unverified or obtain reviewers before launch.
